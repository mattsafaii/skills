# Catalog Load

## Goal

Load a client's catalog into their site repo as committed data, conforming to the object/field contract Structure defined — the Build step between "the map and fields are approved" and "the templates render real products."

The catalog is data, not content: the records, their relationships, and their stable URLs. Code and catalog data live in the repo, not Basecamp. This skill writes the repo; it owns no Basecamp doc.

## Tone

Direct, practical. Report gaps rather than fill them. An empty field is `null` and listed; it is never guessed.

## Gate

Read `Project Context` → `This engagement` → `Catalog in v1`. If it is `none`, there is nothing to load — say so and stop. This skill is for catalog jobs only.

## Required reads, in order

1. **`Project Context`** — at the root of Internal. Read **Business** (name), **Kit** (11ty / GitHub / Cloudflare), and **This engagement** (`Catalog in v1`, the catalog source). **Missing → stop; tell Matt to run `project-setup`.**
2. **`Structure — Fields`** — in Working. This is the object/field contract the data must conform to. **Missing → stop; run `structure-map`.**
3. **`Structure — Sitemap`** — in Working. The pages/templates, and the catalog rules: public vs gated price, and which records are in the first build. **Missing → stop; run `structure-map`.**
4. **The source export** — the client's catalog file (CSV, spreadsheet export, JSON, Airtable export, a folder of PDFs) in the client workspace (`~/Workspaces/safaii-studio/clients/<slug>/`). If its location isn't recorded and isn't obvious, ask Matt.

## Where the data goes (repo)

The site repo is `~/Workspaces/safaii-studio/clients/<slug>/site/`. The 11ty data layer is `src/_data/`:

- **`src/_data/<object>.json`** — one file per object defined in `Structure — Fields` (e.g. `products.json`, `categories.json`). Each file is a list of records; each record conforms to that object's fields.
- **`src/_data/catalog.config.json`** — the **hand-maintained overlay**, kept separate from the loaded data: display order, hidden records, and label overrides. Nothing generated by a re-load lives here, and nothing hand-maintained lives in the data files.

**SQLite is the exception.** Only when Structure chose it (volume or real relations): write the database plus a small 11ty global-data loader that reads it at build. Default is JSON in `_data/`.

## The mapping contract

- **Conform to `Structure — Fields`.** Each record carries exactly the fields that object defines, with the declared type.
- **A source column with no field → flag it** to Matt; do not add a field on your own (that is `structure-map`'s contract to change).
- **A field with no source column → flag it** and leave the value `null`; do not drop the field.
- **Only the first-build slice.** Records Structure's catalog rules exclude do not load. The rest waits for Maintenance.
- **No invention.** No lorem, no placeholder rows, no "three fake items." A missing value is `null` and goes on the gap list.
- **No price logic invented.** Public vs gated price follows Structure's catalog rules exactly.

## Slugs

Every record that maps to a page carries a stable `slug`.

- Derive once, from the record's own name (lowercase, hyphenated), and never churn it.
- **A changed slug is a redirect, not a data edit.** Hand the old→new pair to `structure-redirects`; do not silently rewrite a URL.
- Slugs must be unique within their object; a collision is a finding, not something to auto-suffix.

## What Catalog Load is not

- **Not `structure-map`.** It never edits `Structure — Fields`; mismatches are reported, not fixed here.
- **Not a template or a page.** It writes data; the templates that render it are Build.
- **Not assets.** It writes the references (image paths, document filenames) that records carry; copying images and PDFs into `src/assets/` is a separate Build step. A referenced asset that is missing is reported.
- **Not fabrication.** It never fills a gap with a guess to make the site look complete.

## Checklist

1. **Gate.** `Catalog in v1` ≠ `none`, or stop.
2. **Read in order.** Project Context (missing → `project-setup`); Structure — Fields (missing → `structure-map`); Structure — Sitemap (the first-build slice; public vs gated); the source export.
3. **Map the source to the contract.** For each object in `Structure — Fields`, map source columns to fields. Collect mismatches both ways as findings.
4. **Transform and filter.** Build records for the first-build slice only; derive stable slugs; leave missing values `null`.
5. **Write the data** — `src/_data/<object>.json` (or the SQLite path when chosen).
6. **Write or preserve the overlay** — `src/_data/catalog.config.json` (order, hidden, labels). Never overwrite hand-maintained values; merge.
7. **Verify.** The JSON parses; counts match the source slice; no record violates the contract; slugs are unique; the overlay is intact.
8. **Report and recommend next.** Records per object; unmapped source columns; fields with no source; records missing values (the empty-data list). Next: templates render the records, then `schema-markup`.

## Output format

Checklist with statuses:

| Step | Status | Notes | Next action |
| --- | --- | --- | --- |

Then summarize: gate result, source export used, records loaded per object, the mismatch findings, the missing-value list, files written, and next step.

## Guardrails

- Never invent data, and never write a placeholder row to fill a page.
- Never edit `Structure — Fields`; report mismatches to Matt.
- Never churn a slug — a URL change goes through `structure-redirects`.
- Keep machine-loaded data and the hand-maintained overlay in separate files; a re-load never clobbers order or labels.
- Load only the first-build slice.
- No Basecamp doc — the catalog lives in the repo. Assets stay out of scope.

## Failure modes

| Symptom | Cause | Fix |
|---------|-------|-----|
| Fake or placeholder products in the data | Filled a gap to make the site look complete | Missing values are `null` and reported; never invent rows |
| A field suddenly appears in the data | Source column loaded without a field | Flag the column to Matt; `structure-map` owns the field change |
| A field silently vanished | No source column, so it was dropped | Keep the field, value `null`, and report it |
| Page URLs changed after a re-load | A slug was re-derived or rewritten | Slugs are stable; a real change is a redirect for `structure-redirects` |
| Hand-tuned order or labels lost | Overlay overwritten on re-load | Merge the overlay; never overwrite hand-maintained values |
| Whole catalog loaded, not the slice | First-build rules ignored | Load only the records Structure's catalog rules include |
| Gated prices showing | Public/gated rule ignored | Follow Structure's catalog rules exactly |
| Data written to the wrong place | Wrong data dir for the stack | 11ty uses `src/_data/`; SQLite only when Structure chose it |
| Missing asset looks like a data bug | Assets assumed in scope | The skill writes references; missing assets are reported, copied later in Build |
